# Релиз v1.0.0 — 2026-09-27

Первый версионированный релиз: 192 коммита с начала проекта (2025-07-06), из них 40 (без merge) — после предыдущего состояния `main` (`1ca9a40`). Роутер — OpenAI-совместимый шлюз к нескольким LLM-провайдерам (DeepSeek, z.ai, Kimi, OpenRouter, локальные модели) с контролем доступа по ключам, прозрачным стримингом и учётом расхода. С этого релиза версия видна в `/health`, а проект распространяется под лицензией MIT.

версия: v1.0.0 — выбрана оператором; по коммитам рекомендовался minor (feat×22), но предыдущего тега нет, и контракт для клиентов считается зафиксированным.

# Что умеет роутер

## Для клиентов

- Один эндпоинт для всех провайдеров: `/v1/chat/completions` (стрим и без), `/v1/embeddings`, `/v1/audio/transcriptions`, `/v1/models`, `/v1/models/{id}`, `/v1/capabilities`.
- Стрим пересылается байт в байт; OpenAI-поле `reasoning` дублируется в llama.cpp-поле `reasoning_content`. Ошибка апстрима до первого байта приходит с настоящим HTTP-статусом (401, 429), а не как 200 с ошибкой внутри.
- `/v1/models` отдаёт полный набор возможностей модели: контекст, лимит ответа, модальности, поддерживаемые параметры, цены. Ручной каталог `model_info.yaml` всегда главнее автокэша с апстрима.
- Все ошибки — в формате OpenRouter `{"error": {"code", "message", "metadata"}}`, включая запросы на несуществующие пути.

## Reasoning

- Для каждой модели можно ограничить допустимые значения `reasoning_effort` (`models.yaml` → `reasoning_effort.allowed`): значение вне списка — 400 с именем поля, а не молчаливая подмена.
- Для каждого провайдера задаётся диалект (`providers.yaml` → `reasoning_dialect: openai | deepseek | openrouter`): одна и та же пара `thinking` / `reasoning_effort` от харнесса переводится в форму, которую понимает конкретный апстрим.
- `/v1/capabilities` отдаёт плоскую карту `{supported, effort_levels}` по моделям, доступным ключу.

## Надёжность

- Перезагрузка конфига больше не обрывает идущие стримы: старые пулы соединений закрываются только после того, как допишут свои запросы. Неизменённые провайдеры переживают перезагрузку вместе со своим пулом.
- Если перезагрузка применилась наполовину, в логах это видно как сбой, и она повторяется, а не выглядит успешной.
- Опциональный лимит одновременных запросов на провайдера (`max_concurrent`): лишние ждут слот и получают 503 по таймауту.
- 429 от апстрима повторяются с экспоненциальной задержкой.

## Учёт и статистика

- Одна строка на запрос (включая ошибки) в SQLite, стоимость фиксируется в момент записи по ценам модели.
- Дашборд `/stat/` с разбивкой по ключам и моделям; широкие таблицы прокручиваются внутри карточек.

## Изменения в этой синхронизации, заметные клиентам

- Эндпоинт `/tools/generate_key` удалён; ключи генерирует `scripts/generate_key.py`.
- `/health` отдаёт `{"status": "ok", "version": "…"}` — новое поле, старое не изменилось.

# Действия при обновлении

- `main`: `1ca9a40` → `40f897e` (fast-forward).
- Прод сверен с релизом: `requirements.txt` и `Dockerfile` совпадают, из `src/` отличается только `api/main.py` (поле версии). Обновление — `deploy-server`, code-only: rsync `src/` + запись `src/VERSION` + `docker compose restart`, без пересборки.
- Новых env-переменных нет.
- Конфиги прода не трогаются: `reasoning_dialect` в `providers.yaml` на сервере уже задан, `reasoning_effort` в `models.yaml` опционален.
- Схема usage DB не меняется.
- После деплоя: `ssh docker "curl -s localhost:8777/health"` → `{"status":"ok","version":"v1.0.0"}`.

# Известные ограничения

- Только один uvicorn-воркер (`API_WORKERS=1`): кэш возможностей моделей и запись статистики живут в процессе.
- Список заголовков, которые не пересылаются апстриму при `identity: passthrough`, работает по принципу «запрещено только перечисленное»: неизвестный заголовок клиента уходит апстриму. При подключении нового харнесса или прокси список нужно пересматривать.
