# Audit fixes epic: honest usage stats, quiet reload vetoes, strict config, consistent provider errors

## Decisions

- Size: L, entanglement high (usage-DB write, config hot-reload, `src/providers/base.py`, the streaming request body). Branch `fix/audit-epic` from `dev`. Executor model: Opus. Proof is owed once, at step 5, over `git diff dev...HEAD`: full `tests/` plus a repeat run, `/review`, the live drive in Validation. Intermediate commits owe only `.claude/scripts/pre-commit-gates.sh` (run UNPIPED) and their own targeted tests.
- Every behaviour change below was approved by the operator. Ruling on tests: an existing test that pins a RETIRED behaviour (named per step) is rewritten to the new contract in the same commit; every other existing test stays untouched and green.
- Prices must be numbers. PyYAML reads `prompt: 1e-7` (exponent, no dot) as the STRING `"1e-7"`. `_parse_model_info` (`src/core/config_schema.py:272`) keeps pricing values as-is, and `_compute_cost_usd` (`src/core/usage_db/writer.py:230`) then computes `int * str` = string repetition, so `cost_usd` stores text like `'1e-71e-71e-73e-73e-7'` while `/v1/models` renders the same price correctly. A float mixed with a str raises `TypeError` from `_compute_cost_usd`, which `_flush_row` calls OUTSIDE its `try` (`src/core/usage_db/writer.py:249`), so the whole usage row is lost.
- Fix at both ends. Parse: a new `_parse_pricing(model_id, pricing)` in `src/core/config_schema.py`, called from `_parse_model_info`, turns each value into `float` (int, float, or a numeric string like `"1e-7"`), drops a bool or unparsable value with a `logger.warning` naming the model and key, and drops a non-mapping `pricing` with a warning. Write: `_compute_cost_usd` returns `None` (unpriced row, never a lost one) when any price it would multiply is not an `int`/`float` or is a `bool`. The per-token `INVARIANT:` above `_compute_cost_usd` stays verbatim.
- Streaming usage. llama-server (provider `orange`) sends the usage frame only when the request carries `stream_options: {include_usage: true}`, and harnesses do not send it: `usage.db` shows 251 of 251 successful `orange` streams in 30 days with `has_usage=0`. A live stream to `local/chat` without `stream_options` gets 0 usage frames; with it, the usage is recorded. The stream branch of `ChatService.chat_completions` (`src/services/chat_service/chat_service.py:25`) sets `request_body["stream_options"] = {"include_usage": True}` ONLY when the key `stream_options` is absent. A client-set `stream_options` (including `include_usage: false`) is left exactly as sent. Non-stream requests are never touched. The client now also gets the upstream's final usage chunk (empty `choices`) — accepted by the operator.
- The injection runs before the models.yaml `options:` merge (`src/providers/base.py:170`, `deep_merge` lets the second argument win on leaves), so a model whose `options` sets `stream_options` keeps the operator's value — the same precedence every other option has. No model sets it today (`grep stream_options config/models.yaml` is empty). Mark the injection with `# INVARIANT: a streaming chat request asks the upstream for usage unless the client set stream_options itself; models.yaml options still override it at merge time.` plus `# Why: llama-server emits the usage frame only when asked and harnesses do not ask, so every such stream was recorded with zero tokens and no cost.`
- `ChatService.chat_completions` is grandfathered at 58 lines in `.claude/baselines/func-length.json`. Step 2 moves the stream branch into a `_stream_response(prepared)` method, gets both under 50 lines, and deletes that baseline entry.
- A rejected reload is final for those file bytes. Today `_poll_once` commits `last_mtimes` only when `reload_config()` returns True (`src/core/config_manager.py:372`), so a rejected config is re-read and its rejection re-logged every `config_reload_interval` (5 s) until the file changes. Per cause: a raising pre-swap callback also rebuilds and closes the changed providers and logs ERROR with a traceback (`src/core/config_manager.py:301`); a `ConfigError` logs ERROR without a traceback (`src/core/config_manager.py:266`); a missing section logs WARNING, plus ERROR with a traceback when the cause is a YAML syntax error (`src/core/config_manager.py:150`). Parsing is deterministic and env is frozen per process, so no retry can change the verdict.
- New contract: `reload_config()` returns a `ReloadOutcome` enum defined in `src/core/config_manager.py` with members `APPLIED`, `REJECTED` and `POST_SWAP_FAILED`. `_poll_once` commits `last_mtimes` for `APPLIED` and `REJECTED`, and leaves them uncommitted only for `POST_SWAP_FAILED` (the config is already swapped and the derived cache must catch up — that retry and its `INVARIANT:` in `_log_reload_complete` stay). The next edit of any watched file re-triggers a reload as before.
- Replace the `WHY:` in the `_poll_once` docstring (`src/core/config_manager.py:351`) with: a rejected reload is not retried because the same bytes and the same frozen env always give the same verdict, so a retry only repeats the rejection; its one log line per file change is the signal. Update the `reload_config` docstring's Returns block to the three outcomes, and the comment in `_parse_for_reload` (`src/core/config_manager.py:264`) that says "the next poll retries" to say the next file change retries.
- Retired tests for step 3 in `tests/unit/test_config_manager.py`: `test_failed_reload_leaves_mtimes_unchanged` (line 668) becomes "a vetoed reload commits last_mtimes and the second `_poll_once` returns False". Every `assert await cm.reload_config() is True/False` in that file is re-pointed to the matching `ReloadOutcome` member. `test_post_swap_failure_leaves_mtimes_uncommitted` (line 683) keeps its assertions.
- `max_concurrent` is a hard check. `parse_provider` passes `raw.get("max_concurrent")` through unchecked (`src/core/config_schema.py:216`), and `ProviderPool` then silently disables the gate for a string like `"3"` and turns `true` into `Semaphore(1)` (`src/providers/pool.py:56`). `parse_provider` raises `ConfigError` unless the value is absent/null or an `int` that is not a `bool` and is `> 0`. `ProviderPool` is not changed; its existing defensive test (`tests/unit/test_base_provider.py:544`) stays.
- Cross-file references are a soft check. `parse_config` (`src/core/config_schema.py:325`) logs one `logger.warning` per model whose `provider` is not a key of `providers`, and one per `user_keys` entry naming an `allowed_models` id that is not in `models`. Nothing is dropped and no reload is vetoed — the same class as the existing model_info orphan warning (`src/core/config_schema.py:291`).
- Malformed env refuses startup. `_env_number` (`src/core/config_manager.py:78`) falls back to the default with a warning, and `_env_bool` (`src/core/config_manager.py:73`) reads anything that is not `true` as False — both contradict the module's `ARCH:` (`src/core/config_manager.py:18`), which promises startup fail-fast. `_read_env_settings` collects every malformed value (a numeric field that does not parse; a bool field whose stripped, lower-cased value is not `true` or `false`) and raises one `RuntimeError` naming each variable and its raw value. Unset variables keep their defaults, and so do bool and numeric variables whose value is empty or whitespace-only (`MODEL_CACHE_ENABLED=` means unset, not malformed); str fields keep today's behaviour. The `ARCH:` text is then true and stays as is.
- Retired tests for step 4 in `tests/unit/test_config_manager.py`: `test_malformed_env_falls_back_to_default` (line 341) and `test_malformed_number_falls_back_to_default` (line 430) become `pytest.raises(RuntimeError)` whose message names `QUEUE_WAIT_TIMEOUT`.
- Same condition, same status. A stream request maps `httpx.PoolTimeout` to 503 `service_unavailable` (`src/providers/base.py:399`), while the non-stream path lets it fall into `httpx.RequestError` and answers 500 `provider_network_error` (`src/providers/base.py:319`). `_send_once` gets an `except httpx.PoolTimeout` arm ABOVE the `RequestError` arm, with the same `create_error(ErrorType.SERVICE_UNAVAILABLE, error_details="Connection pool exhausted. Please retry later.", ...)` call the stream path uses.
- Log noise on stream errors. `_stream_request_inner` ends with `except Exception` (`src/providers/base.py:411`), which also catches the `HTTPException` that `_check_stream_response` raises for an upstream 4xx/5xx and logs it at ERROR with a full traceback. `log_provider_error` has already logged that error. Add `except HTTPException: raise` (from `fastapi`) directly above it, so an upstream 429 in a stream is logged once, by the provider-error channel.

## Risks

- A deploy host whose `.env` holds a malformed value that today silently falls back will refuse to start after step 4. Signal, checked on the server before deploying: `grep "has invalid value" logs/app.log*` for numeric variables, and `grep "^MODEL_CACHE_ENABLED" .env` for the only bool variable, whose value must be `true`, `false` or empty — `_env_bool` reads anything else as False today without logging, so the log grep cannot find it.
- An upstream may reject the `stream_options` field with a 400. Signal: a streaming request to any chat model in Validation answers non-200.
- A harness that cannot handle a chunk with empty `choices` would break on the injected usage chunk. Signal: an error report from a harness after deploy.
- Committing `last_mtimes` on a rejected reload means an editor that writes a file in two steps is detected only if the second write bumps the mtime again. Signal: a fixed file that is not picked up (no "Configuration reloaded" line within 10 s).
- Cross-reference warnings are logged on every reload of any config file. Signal: the same warning block repeating on unrelated edits — expected, not a defect.
- The `ReloadOutcome` change touches every `reload_config` assertion. Signal: a test in `tests/unit/test_config_manager.py` failing on an `is True`/`is False` comparison.
