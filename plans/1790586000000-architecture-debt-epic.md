# Architecture debt epic: restore layering, type the config, collapse single-adapter seams

## Decisions

- Size: L, entanglement high (auth, config hot-reload, provider pool lifecycle, SSE path, usage-DB write are all touched). Branch `refactor/architecture-debt` from `dev`. Executor model: Opus. Proof is owed once, at step 7, over `git diff dev...HEAD`.
- Target dependency direction is `api -> services -> providers -> core`, and `core` imports nothing above it. Today four edges point the wrong way; each is removed by a step below and none is re-added.
- Wrong edges 1 and 2 (`core/config_manager.py` and `providers/base.py` importing `services.reasoning_*`): done in step 2 — the validation they imported now lives in `src/core/config_schema.py:193`.
- Wrong edge 3: `src/core/model_capabilities/refresh.py:12` imports the provider registry. Fixed in step 4 by moving the refresh orchestration to `src/services/capabilities_refresh.py` (it orchestrates providers; it is not a core concern). `cache.py`, `normalizers.py`, `render.py` stay in core.
- Wrong edge 4: `src/core/usage_db/writer.py:193` duck-types `app_state.model_service` to price a row, and `src/api/middleware.py:129` threads `app_state` down for it. Fixed in step 6: `init_db(db_path, pricing_lookup)` stores a `Callable[[str], dict | None]`; `lifespan` passes `model_service.get_pricing`; `app_state` leaves `schedule_flush`, `_flush_row` and the middleware.
- Typed config (done in step 2): the YAML is parsed once by `parse_config` (`src/core/config_schema.py:325`); the funnel reads `ModelEntry.effort_policy` and `ProviderEntry.reasoning_dialect` and never re-validates.
- `src/core/config_schema.py` holds frozen `EffortPolicy`, `ProviderEntry`, `ModelEntry`, `KeyEntry`, `RouterConfig(providers, models, user_keys, model_info)`, `parse_config` and `ConfigError`; `model_info` stays `dict[str, dict]` (the stored capability shape). `services/reasoning_effort.py` and `services/reasoning_dialect.py` keep only the request-body transforms.
- Soft vs hard validation (done in step 2). Soft (warn + drop, never vetoes a reload): the effort block (`src/core/config_schema.py:220`) and model_info keys (`src/core/config_schema.py:272`). Hard: unknown `type`, `reasoning_dialect`, `identity`, malformed static `headers:`, non-mapping entries — `parse_config` raises `ConfigError` listing every bad entry; startup refuses to start, `reload_config` logs it and returns False with the old config kept (`src/core/config_manager.py:239`). Env-dependent checks (`base_url`, the `api_key_env` variable) stay at provider construction.
- Dead auth branch (`config is None or "user_keys" not in config`): deleted in step 2; `_missing_sections` (`src/core/config_manager.py:159`) is the gate that made it unreachable.
- Single-adapter seam: there is one provider type. `BaseProvider` (`src/providers/base.py:39`) carries five `NotImplementedError` stubs (`src/providers/base.py:474`) for its only subclass `OpenAICompatibleProvider` (`src/providers/openai.py:9`), which the registry factory constructs directly (`src/providers/__init__.py:50`). Step 3 merges them into one `Provider` class in `src/providers/base.py` (keeps the `SYSTEM: provider` entry file) and deletes `src/providers/openai.py`. `type: openai` stays a required, validated key so a second type can come back without a config change.
- The non-stream request path is three stacked methods passing the same eight keyword arguments (`src/providers/base.py:221`, `src/providers/base.py:248`, `src/providers/base.py:290`). Step 3 reduces them to `_request` (holds the slot, runs the 429 loop) and `_send_once` (one attempt). Retry semantics, the `_is_rate_limit_error` helper and every existing `WHY:` move verbatim.
- `_stream_request` takes a `client` argument that is always `self.pool.client` (`src/providers/base.py:364`, sole caller `src/providers/openai.py:37`); step 3 drops it. The per-chunk `logger.debug` lines inside the provider stream loop (`src/providers/base.py:448`) duplicate the debug chunk preview the stream processor already emits; step 3 deletes them.
- `provider_name` becomes required; the class-name fallback (`src/providers/base.py:67`) has no caller that omits the name.
- The provider registry is module globals (`src/providers/__init__.py:18`, `src/providers/__init__.py:22`) reached through a module-level function. Tests reach it by `patch("src.services.base.get_provider_instance")` 18 times and poke `._provider_cache` 40 times — the growth signal from `testing.md`. Step 4 makes it a `ProviderRegistry` class (same file) with `prepare`, `publish`, `get`, `aclose_all`; one instance is built in `lifespan`, stored on `app.state.provider_registry`, and passed to the services and to the capabilities refresh. Prod plus test registry are two adapters, so this is a real seam. The three `INVARIANT:` blocks in that file move verbatim onto the matching methods.
- Config/cache consistency window: `_resolve_target` takes `provider_config` from the config dict (`src/services/base.py:147`) and the instance from the cache (`src/services/base.py:198`); across a reload these can be two different generations, so the dialect applied can belong to an entry the called backend was not built from. The instance already carries its own entry (`src/providers/base.py:71`, `self.entry`). Step 5 drops `ResolvedTarget.provider_config` and translates using `target.provider.entry`.
- Duplicated access resolver: `retrieve_model` re-implements the allowed -> exists -> provider-exists chain (`src/services/model_service.py:177`) beside `_validate_and_get_config` (`src/services/base.py:122`). Step 5 makes both call one `resolve_model(model_id, auth_context, **error_ctx)` on the service base; the access-before-existence `INVARIANT:` lives once, on that function.
- Dead or pass-through service members, deleted in step 5: `ChatService.model_service` (`src/services/chat_service/chat_service.py:20`) and `TranscriptionService.model_service` (`src/services/transcription_service.py:24`) have no reader; `_get_request_context` (`src/services/base.py:86`) and `_log_service_data` (`src/services/base.py:248`) only forward to `request_context` and `logger.debug_data`; `ModelService`'s optional `capabilities_cache` (`src/services/model_service.py:30`) is always passed in prod, so its three `None` branches go.
- `StreamProcessor` holds no state; `__init__` only logs (`src/services/chat_service/stream_processor.py:94`). Step 5 turns it into a module function `process_stream(...)` and makes `stats` required — the `RequestStats()` throwaway (`src/services/chat_service/stream_processor.py:121`) exists only for tests, which will pass their own holder.
- Logger `exc_info` forwarding at every level and the dead `ConfigManager.debug`/`log_level`: done in step 1 (`src/core/logging/logger.py:55`).
- Dashboard queries map rows by index (`src/core/usage_db/queries.py:355`); step 6 sets `conn.row_factory = aiosqlite.Row` in `init_db` and aliases the SQL columns to the JSON keys so `dict(row)` is the mapping. The JSON returned by every `/stat/api/*` endpoint stays byte-identical.
- Functions over 50 lines split in their own step so the func-length baseline shrinks: `BaseProvider.__init__` (if still listed), `_make_request_attempt`, `_stream_request_inner` (step 3); `ProviderPool.__init__` if touched (step 4); `TranscriptionService.create_transcription`, `ModelService.retrieve_model`, `StreamProcessor.process_stream` (step 5); `RequestLoggerMiddleware.__call__`, `get_api_key`, `get_requests`, `get_summary`, `get_usage_data` (step 6). Each removed entry is deleted from `.claude/baselines/func-length.json` in the commit that fixed it.
- Ruling on tests: a test that reaches past the interface (a `patch("src.…")` target, `monkeypatch.setattr`, private attribute access) is re-pointed to the new interface in the step that moved it; its expected values do not change. A step that would need to change an expected value is a behaviour change and stops for the operator.
- Every relocated `ARCH:`/`INVARIANT:`/`WHY:` is moved verbatim (`documentation.md`, "a contract that moves carries its existing words"); only process provenance in a touched file's header is stripped.

## Risks

- Typed config touches every config reader at once (step 2). Signal: an `AttributeError`/`TypeError` surfacing as a 500 in `tests/api/` or `tests/unit/`.
- Veto semantics move from provider construction into `parse_config`. Signal: a providers.yaml with `reasoning_dialect: typo` must be rejected on reload with the old config still serving; `tests/unit/test_config_manager.py` gains that case.
- Instance reuse compares `ProviderEntry` values (`src/providers/__init__.py:107`). If equality drifts, every models.yaml edit rebuilds every pool and resets semaphores. Signal: after touching models.yaml the log shows no new "concurrency limit enabled" / "has no concurrency limit" lines.
- Registry ordering: publish must stay the FIRST post-swap callback and drain old-minus-published by identity. Signal: `tests/unit/test_provider_registry.py`, plus the live reload during an open stream in Validation.
- The SSE path is touched in steps 3 and 5. Signal: `curl -N` frames differ from upstream, or a `[DONE]` appears where the upstream sent none.
- Cost freezing moves to an injected lookup. Signal: a new usage row for a priced model has `cost_usd` NULL.
- Foreign work in flight: `src/services/chat_service/stream_processor.py` and `tests/unit/test_stream_processor.py` carry uncommitted edits for `plans/1789479250000-upstream-stream-error-frames.md`. Step 5 rewrites that file; branching before those edits land loses them. Signal: `git status` on `dev` not clean for those paths when the branch is cut.

## Order

1. Logger + dead config fields. In `src/core/logging/logger.py` collapse `info/debug/warning/error` into one `_log(level, message, **kwargs)` forwarding `exc_info`; keep the public method names. Delete `ConfigManager.debug`/`log_level` and their init-log keys. Test in `tests/unit/test_logging_config.py`: `logger.warning("x", exc_info=True)` inside `except` yields a record with `exc_info` set, for every level. This plan file rides in this commit.
2. Typed config. Add `src/core/config_schema.py` (dataclasses + `parse_config` + `ConfigError`), move the effort-policy and dialect validation into it, make `ConfigManager.get_config()` return `RouterConfig`, and migrate every reader: `src/core/auth.py`, `src/services/base.py`, `src/services/model_service.py`, `src/services/reasoning_effort.py`, `src/services/reasoning_dialect.py`, `src/core/model_capabilities/refresh.py`, `src/providers/__init__.py`, `src/providers/base.py`, `src/api/main.py`, `scripts/dump_model_info.py`. Delete `resolve_dialect`, the per-request re-parse and the auth dead branch. Tests build configs through `parse_config(dict)`; new cases: bad dialect vetoes reload and keeps the old config; bad effort block is dropped with a warning; unknown provider type is a `ConfigError`.
3. One provider class. Merge `OpenAICompatibleProvider` into `Provider` in `src/providers/base.py`, delete `src/providers/openai.py`, collapse the request triple into `_request`/`_send_once`, drop the `client` parameter and the per-chunk debug lines, make `provider_name` required, split `__init__` (static-header validation into its own function). Rename references in `src/providers/__init__.py`, `src/services/base.py` and tests.
4. Registry object. `ProviderRegistry` in `src/providers/__init__.py`; build in `lifespan`, store on `app.state.provider_registry`, pass to `BaseService.__init__` and to the capabilities refresh. Move `src/core/model_capabilities/refresh.py` to `src/services/capabilities_refresh.py`; update `src/core/model_capabilities/__init__.py` exports and the docstring's module list. Re-point the 18 `get_provider_instance` patches and the `_provider_cache` pokes to a registry instance. Regenerate `SYSTEMS.md`.
5. Service layer. Prerequisite: the upstream-stream-error-frames change is committed on `dev` and this branch is rebased onto it. One `resolve_model` shared by dispatch and `retrieve_model`; drop `ResolvedTarget.provider_config` and translate from `target.provider.entry`; delete the dead `model_service` fields, the two pass-throughs and the optional-cache branches; `StreamProcessor` becomes `process_stream` with required `stats`; split `create_transcription`, `retrieve_model`, `process_stream` under 50 lines. Update `src/api/main.py` construction and `src/services/chat_service/__init__.py` exports.
6. Split `RequestLoggerMiddleware.__call__` and `get_api_key` under 50 lines. Test: every `/stat/api/*` response over a seeded DB equals the pre-change JSON captured in the test.
7. Docs, gates, acceptance. `CLAUDE.md`: Upstream Identity paragraph says identity is opt-in per provider (unset = plain gateway headers, as `src/core/config_schema.py:148` and `config/providers.yaml:6` already say); Provider Abstraction paragraph names the single `Provider` class and the `ProviderRegistry` object. `.claude/rules-scoped/providers.md:14` ("Format translation happens in the provider") is replaced by the funnel ruling in `src/services/reasoning_dialect.py`. Each rules/CLAUDE.md edit carries an `Observation / Rule / File` block with verbatim output from this session. Shrink `.claude/baselines/func-length.json`, run `python3 .claude/scripts/systems-index.py --write`, then the full Validation below and `/review` over `git diff dev...HEAD`.

- Routing the hand-built envelopes in `src/api/stat_routes.py` and the unhandled-500 handler in `src/api/main.py` through `ErrorType` — it adds `metadata.error_code` to responses clients read; that is an operator decision.
- Changing `deep_merge` list-concatenation semantics for models.yaml `options:` — a request-body behaviour change.
- Migrating the `extra={...}` logging call sites to kwargs.
- Moving process-local state out of process for multiple workers.
- Replacing the linear constant-time key scan in auth.
- Moving `src/utils/generate_key.py` into `scripts/` — its root is the operator CLI and it costs nothing.
